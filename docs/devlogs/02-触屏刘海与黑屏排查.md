《改道》是个网格塔防，核心玩法是放墙把敌人往远处推——绕得越远，击杀赏金越高。上一期在电脑上把模拟层迁完，这一期的主要目标是**把它装进手机**。

【本期进展】

安卓包先跑通了：Java 21 环境、导出配置、纹理压缩（ETC2/ASTC，老手机显存友好）都配好，正式包约 283 MB，签名 CN=Reroute，`apksigner verify` 校验通过。

触屏拖线最后一行新代码都没写。Godot 默认会把触摸换算成鼠标事件（`emulate_mouse_from_touch`），我先做了对拍验证：「触点拖线」和「鼠标拖线」得到的世界状态逐字节一致，于是直接沿用引擎换算——自己再写一套触摸分支反而会导致真机上双重处理。

刘海和全面屏也处理了：视口策略改成「高度固定 720、宽度随屏幕比例展开」，外加一层安全区，HUD 和按钮整体躲开刘海与手势条。1600×720（20:9）和窄屏各截了一张，不越界、不遮挡。

最后在安卓模拟器（MuMu）上装了包，完整跑通一局：主菜单 → 开打 → 触屏放墙扣费 300→290、墙上屏 → 失守结算「防线失守 0:46」→ 再来一局放塔。全程无崩溃。

顺手也把世界从 48×48 扩到了 64×64，地形渲染换成一张连续的水密网格，去掉了原来一圈「围墙感」。

【问题与风险】

本期最大惊吓：正式包在模拟器上黑屏，日志只有一行 `Couldn't present to Vulkan queue`。排查了一整圈——宿主渲染模式各种组合都试了、拆包确认没有传参机制、上游也有一模一样的「模拟器黑屏、真机正常」issue。结论：是模拟器虚拟 Vulkan 不兼容，与游戏无关。用同一份代码只换 GL 后端出验收包，链路一次全绿。提审包仍用 Vulkan，真机上再复验一眼。

探针环节给了一个教学时刻：模拟注入事件时，`push_input` 是旁路的，世界区根本收不到；必须用 `parse_input_event` 走真实链路，逐字节对拍才算有效证据。

Windows 包遇到的是本机特有的坑：Smart App Control 拦未签名 exe。已自签（CN=Reroute）并本机验证通过；但自签在别人的机器上不生效，这条先记为发行注意事项。

诚实账：安卓目前只验到模拟器，真机装机还没做；刘海尺寸也是探针模拟注入的，等真机再确认一遍。

【下期计划】

真机装机 + 找人试玩（至少 2 人各 2 局），记录卡点和第一局结局；按反馈调数值，然后冻结。上传提审素材（讲解视频 / 实机视频 / 五图）。下一篇日志讲试玩反馈。
