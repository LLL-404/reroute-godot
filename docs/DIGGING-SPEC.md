# 《改道》挖矿改造规格（DIGGING-SPEC）

> 状态：**规格已裁定，未开工**。
> 来源：2026-10-21 与 BOSS 的四轮拷问（15 项选择题 + 1 项「两个都要」）。
> 定位：**替换主模式的挖矿核心**，主模式与肉鸽**同时生效**。
> U01 复核：英雄 HP 与「被动打断 −30% 进度」**并存生效**，不做取舍。
> 前置事实：现有挖矿 = 玩家点格即时生效（`sim/world.gd:135`），零耗时、零位置成本、与英雄零耦合。

## 2 规则状态机

### 2.1 矿格状态

```
[READY] --英雄挖满 50 tick--> [DEPLETED] --1200 tick--> [READY]
   ^                              |
   |                              +--玩家点挖被拒（不改变状态）
```

| 状态 | 格子地形 | 可否点挖 | 可否英雄挖 | 视图 |
|---|---|---|---|---|
| `READY` | `COVER`（未挖开）/ `OPEN`（刷新后） | **拒** | **可** | 矿模型可见 |
| `DEPLETED` | `OPEN`（挖开即永久 OPEN） | 允许（按土方收费 15） | 拒（无矿） | 矿模型隐藏 |
| 非矿格 `COVER` | `COVER` | 允许（15） | 拒 | 无矿 |

**硬规则**：

- MUST 让 `READY` 状态与格子是否为 `COVER` **解耦**。刷新不重建 `COVER`，只切 `ready` 布尔。
- MUST NOT 允许玩家点挖 `READY` 矿格——包括盆地插口（插口本身是矿格，见 §5.3）。
- NEVER 在 `DEPLETED` 的矿格上自动重新挂矿模型而不更新 `ore_state`。

### 2.2 英雄状态

```
[IDLE] --点矿格--> [WALK_TO_ORE] --到达邻格--> [DIGGING] --50 tick--> [IDLE]（+35 supply，矿格→OPEN）
   ^                     |                    |   |
   |                     |                    |   +--敌进 2 格--> [INTERRUPTED]（进度 ×70%）
   |                     |                    +------玩家点别处 / 放技能--> [INTERRUPTED]（进度 100%）
   |                     +---------------------------路径不可达--> [IDLE]（无提示，静默失败）
   +-------------------------------------------------HP ≤ 0--> [DEAD]（进度立即归零）--160 tick--> [REVIVE]（核心邻格满血）
```

### 2.3 站位规则

| 项 | 规则 |
|---|---|
| 开挖位置 | 目标矿格的**六邻之一**，且该邻格 `passable` 且无建筑 |
| 选格顺序 | 玩家点击时由 `main` 侧选「离英雄最近的可站邻格」，平手取方向序最小 |
| 占位冲突 | 邻格有敌人单位时仍可开挖（不检查 `cell_vacant`，只检查建筑与地形） |
| 移动中矿格被他人挖开 | 到达后检测目标格已 `OPEN` → 直接 `IDLE`，不产出 |

| 状态 | 可否移动 | 可否放震荡波 | 可否被攻击 | 进度 |
|---|---|---|---|---|
| `IDLE` | 是 | 是 | 是（邻格） | — |
| `WALK_TO_ORE` | 是（自行走到目标） | 是 | 是 | — |
| `DIGGING` | **否**（站定） | **是**（放技能立即中断，不掉进度） | 是（邻格） | 累积 |
| `INTERRUPTED` | 是 | 是 | 是 | **被动 −30% / 主动 保留** |
| `DEAD` | 否 | 否 | 否 | **归零** |

**三种中断的原因分离（硬规则）**：

| 触发源 | 进度处理 | 依据 |
|---|---|---|
| 敌人进入 2 格（高度差 ≤1） | **×70%，向下取整** | 被动损失，玩家无法规避 |
| 玩家点别处 / 放震荡波 / 手动取消 | **100% 保留** | 主动选择，不惩罚 |
| 英雄死亡 | **归零** | 惩罚最重，与复活共同构成死亡代价 |
| 目标格矿量被清空（并发） | 归零 | 理论上不可达（单英雄） |

## 3 数值表

### 3.1 常量（`sim/sim.gd`）

| 常量 | 旧值 | 新值 | 推导 |
|---|---|---|---|
| `ORE_YIELD` | 25 | **35** | 挖矿从 0 s 变 2.5 s，+40% 补偿 |
| `DIG_COST` | —（免费） | **15** | 与 `FILL_COST` 同价：一次土方 = 一次填高 |
| `HERO_HP_MAX` | — | **600** | 3 只虫围咬（40 DPS）撑 15 s；1 只蛮兽（50 DPS）撑 12 s |
| `HERO_DIG_TICKS` | — | **50** | D03 |
| `HERO_DIG_INTERRUPT_R` | — | **2** | D05（hex 距离，含高度差 ≤1 过滤） |
| `HERO_DIG_BACKSLIDE` | — | **30** | 被动打断时扣减百分比；`progress = progress * 70 / 100`（整数除，向下取整） |
| `HERO_REGEN_DELAY` | — | **60**（3 s） | 脱战判定 |
| `HERO_REGEN_RATE` | — | **1.5 HP/tick**（30 HP/s） | 空血回满 20 s |
| `HERO_REVIVE_TICKS` | — | **160**（8 s） | 主模式 320 s 的 2.5% |
| `ORE_RESPAWN_TICKS` | — | **1200**（60 s） | D08 |
| `CORE_REGEN_MULT` | — | **2.0** | 核心 4 格内回血加倍 |

### 3.2 英雄受击

| 项 | 规则 |
|---|---|
| 谁能打英雄 | 敌人单位，**仅当英雄在其攻击范围内** |
| 目标优先级 | 建筑优先；**英雄在邻格（≤1）时改为打英雄** |
| 伤害 | 虫群 8 / 蛮兽 60（同建筑伤害，不另设表） |
| 冷却 | 虫群 12 tick / 蛮兽 24 tick（同上） |
| 打断 | 受击瞬间中断挖矿，**进度 ×70%（向下取整）** |

**推导**：不改 `find_attack_target` 的返回结构，只在 `unit_tick` 里加一条前置分支——若英雄在邻格，目标改指英雄。这样对现有建筑气流的扰动面最小。

### 3.3 挖矿速率对照

| 矿源 | 格数 | 供给速率 | 前置代价 |
|---|---|---|---|
| 中场（安全） | 5 | 2.9 supply/s | 无 |
| 盆地（诱饵） | ≥10 | 5.8 supply/s | 挖插口 = 开第三出怪口 + 每 300 tick 漏 2 只虫 |
| 英雄单次挖掘 | — | 14 supply/s（35 ÷ 2.5 s） | 英雄被绑 2.5 s + 走位 |

**打断对速率的影响**（用于平衡评估）：

| 干扰强度 | 单格实际耗时 | 等效速率 |
|---|---|---|
| 无干扰 | 50 tick | 14.0 supply/s |
| 每轮挖到 49 tick 被打断一次 | 49 + 16 = 65 tick | 10.8 supply/s |
| 每轮挖到 25 tick 被打断一次 | 25 + 33 = 58 tick | 12.1 supply/s |
| 每 10 tick 被打断一次 | **不收敛**（极限 `p* = 23.3`，永远到不了 50） | **≈ 0**，必须先清场 |

结论：30% 的惩罚对「偶尔被顶」只损 20–25%，对「持续被骚扰」是断崖式归零。这正是想要的形状——**矿点周围安不安全，决定挖矿是否成立**，而不是单纯把时间拉长。

### 3.4 死亡与复活

| 项 | 规则 |
|---|---|
| 触发 | `hp ≤ 0` |
| 表现 | 英雄模型消失 / 倒地，160 tick 后核心邻格重生 |
| 死亡损失 | 当前挖掘进度**归零**；身上无携带物（不做搬运） |
| 复活位置 | 核心邻格中第一个可通行格（按 `sc.core` 周围顺时针探测） |
| 复活时 HP | 满血 |
| 死亡期间 | 所有英雄指令被忽略，UI 显示倒计时 |

## 4 交互契约

| 玩家动作 | 系统响应 | 失败提示 |
|---|---|---|
| 点 `READY` 矿格（模式=挖） | **拒绝**，格子幽灵标红 | 「矿需本人到场」 |
| 点非矿 `COVER` 格（模式=挖） | 扣 15 supply，`COVER→OPEN` | supply 不足 → 红幽灵，无扣费 |
| 点 `DEPLETED` 矿格（模式=挖） | 按土方处理，扣 15 | 同上 |
| 点矿格（模式=英雄移动） | 英雄前往，到达后**自动开挖** | 不可达 → 音效，英雄不动 |
| 挖矿中点地面 | 中断（**主动 → 进度 100%**），英雄前往 | — |
| 挖矿中点「震荡波」 | 立即施放 + 中断（**主动 → 进度 100%**） | CD 中 → 无响应 |
| 挖矿中敌进 2 格 | 中断（**被动 → 进度 ×70%**），英雄原地不动 | 屏幕边缘闪红一次 |
| 挖矿中打开暂停 | 冻结，`DIGGING` 保持 | — |
| 挖矿中切到 INTRO/PICK（肉鸽） | **世界不 tick，挖矿冻结** | 见 R5 |

**硬规则**：

- MUST 用 `mode_valid("dig", x, y)` 拦截 `READY` 矿格，且**在 `apply_command` 里二次守卫**（双保险，防脚本/存档绕过）。
- MUST NOT 让「模式=挖」对矿格产生任何扣费——拒绝要在扣费之前。
- NEVER 允许英雄在 `COVER` 格上开挖（矿格未挖开时英雄走不进去）——开挖一律发生在**邻格**，见 §2.3。
- MUST 让 `_hero_abort_dig(reason)` 显式接收原因枚举（`PASSIVE_HIT` / `PLAYER_CANCEL` / `CAST_SKILL` / `DEATH`），**禁止在调用点手写进度乘法**——扣减逻辑只允许出现在函数体内一处。

## 5 地形与地图契约

### 5.1 矿格清单（不变）

| 组 | 数量 | 位置 | 校验 |
|---|---|---|---|
| `mid_ore` | 5 | 北岸中场 | `scenario.gd:363` 已锁 |
| `basin_ore` | ≥10 | 盆地内腔 | 同上 |

### 5.2 刷新不破坏建造

| 场景 | 规则 |
|---|---|
| 玩家在 `DEPLETED` 矿格上建塔/墙 | 允许（格子是 `OPEN`） |
| 该格冷却结束后 | **不再刷新矿**（`ore_state` 标记为 `BLOCKED`），直到建筑被拆 |
| 建筑被拆后 | 下一 tick 重新进入冷却计时 |
| 存档 | `ore_state` 全部序列化（见 §6.2） |

### 5.3 盆地插口 = 矿格

`scenario.gd:133` 的 `basin_plug` 同时是 `basin_ore[0]`。

- 语义后果：**玩家点挖开不了盆地**，必须派英雄亲自钻进去挖。
- 这是本改造的**核心收益**：开门陷阱从「花 15 块点一下」升级为「把唯一的机动单位押进去」。
- MUST 在 HUD 首次点击插口时给出明确提示，避免玩家以为是 bug。

## 9 验收

### 9.1 老闸处置

| 闸 | 处置 |
|---|---|
| `probe_golden` 16 指纹 | **必然失效**，需重建基线（`ORE_YIELD` / `dig` 收费 / 英雄 HP 全变） |
| 剧本指纹 `0x7dea2b02` | 若含 `ore_cells` 序列化则不变；否则重算 |
| `selfcheck` 33 项 | 加 4 项（矿拒绝 / 收费 / 刷新 / 复活） |

### 9.2 新增 `probe_dig.gd` 断言

| # | 断言 |
|---|---|
| A1 | 点 `READY` 矿格 → supply 不变，格子仍 `READY` |
| A2 | 点非矿 `COVER` → supply −15，格子 `OPEN` |
| A3 | 英雄站在矿格邻格 → 恰好 50 tick 后 +35，矿格 `COVER→OPEN` |
| A3b | 英雄站在矿格本身（已 `OPEN` 的刷新矿）→ 也可开挖，视为邻格距离 0 |
| A4 | 第 49 tick **主动**取消 → 进度 49，再挖 1 tick 即完成 |
| A4b | 第 49 tick **被动**打断 → 进度 34（`49*70/100`），再挖 16 tick 完成 |
| A4c | 第 1 tick 被动打断 → 进度 0（整数除向下取整的边界，断言不崩溃、不出现负数） |
| A5 | 敌进 3 格不中断，进 2 格中断 |
| A6 | 高度差 ≥2 的敌人不中断 |
| A7 | 挖矿中 `hp→0` → 进度归零，160 tick 后核心邻格满血复活 |
| A8 | 挖空 1200 tick 后同格恢复 `READY`，格子仍 `OPEN` |
| A9 | 在 `DEPLETED` 格上建塔 → 冷却结束后不刷新 |
| A10 | 读档后 `ore_state` 与英雄进度一致 |

### 9.3 跑批

| 项 | 口径 |
|---|---|
| 主模式 | 固定种子 × 3 布局，人工通关可行性（bot 到核心不破） |

| 死亡 | 一局英雄死亡次数 ≤ 2（超过则 HP/回血失衡） |

## 11 异常处理表

| 异常 | 处理 |
|---|---|
| 英雄目标矿格被拆掉的建筑挡住 | 路径不可达 → 静默放弃，英雄停在原地 |
| 英雄挖矿中格子被填高 / 挖低（`fill`/`lower` 守卫已排除英雄所在格） | 不冲突 |
| 英雄挖矿中该格被建成塔 | 不可能（`by_cell` 守卫拦截建造） |
| 两个英雄 | 不存在，单英雄 |
| 复活点全被占 | 核心邻格探测失败 → 顺延到距离核心最近的空 `OPEN` 格 |
| 存档发生在 `DIGGING` 中 | 读档后回到 `INTERRUPTED`，进度**按 100% 保留**（存档不算被动打断） |
| 进度扣减后小于 1 | 归零，不出现负数；下次开挖从 0 开始 |
| 同一 tick 内既受击又被玩家点走 | `PASSIVE_HIT` 优先，扣 30% |
| 肉鸽 PICK 期间矿冷却走完 | 冻结，回到 WAVE 后继续计时 |
| 敌人在英雄挖矿格上生成 | 立即中断（生成即进入 2 格） |
